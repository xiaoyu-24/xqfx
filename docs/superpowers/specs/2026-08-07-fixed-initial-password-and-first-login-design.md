# 固定初始密码与首次登录改密设计

## 目标

统一用户创建和管理员重置密码的初始密码为 `888888`，并确保用户首次登录或密码被管理员重置后，必须先完成改密才能进入系统。

## 范围

- 后端 `UserService.createUser` 使用固定初始密码 `888888`。
- 后端 `UserService.resetPassword` 使用固定初始密码 `888888`，保留现有会话失效逻辑。
- `UserEntity.resetPassword` 继续设置 `mustChangePassword=true`，清除登录失败次数和锁定状态。
- 前端创建成功提示只显示“用户已创建”，不再显示随机密码。
- 前端重置密码提示说明新初始密码为 `888888`，并提示首次登录需要修改。
- 登录接口返回的 `mustChangePassword` 由现有 `UserResponse` 传递到登录页；登录页在该字段为真时展示改密表单，改密成功后才进入主界面。

## 数据流

1. 创建用户或管理员重置密码时，服务端用 `888888` 生成 BCrypt 哈希并写入 `password_hash`。
2. 同一操作将 `must_change_password` 设为真，清除失败次数和锁定时间；重置密码时清除该用户全部会话。
3. 用户使用账号和 `888888` 登录，服务端建立会话并返回 `mustChangePassword=true`。
4. 前端停留在登录页的改密阶段，提交当前密码和新密码到 `/api/auth/change-password`。
5. 服务端更新哈希、将 `must_change_password` 设为假并清除全部会话；前端回到登录阶段，用户使用新密码重新登录。

## 错误处理

- 创建、重置密码的现有异常响应保持不变。
- 首次登录改密校验继续使用现有规则：新密码至少 8 位，且两次输入一致。
- 若登录接口没有返回 `mustChangePassword` 或值为假，前端按普通登录流程进入主界面；不新增绕过后端校验的前端逻辑。

## 测试与验收

- 后端测试验证新建用户的初始密码为 `888888`，登录响应标记 `mustChangePassword=true`。
- 后端测试验证管理员重置后的密码为 `888888`、旧会话失效且仍要求改密。
- 前端构建通过，并手动验证创建提示、重置提示、首次登录改密流程。
- 验收结果：新建用户和重置后的用户均可用 `888888` 登录；首次登录不进入业务主界面，完成改密后才能进入。

## 安全说明

固定初始密码降低了部署和转交成本，但所有用户共享同一初始密码。系统必须继续强制首次改密；部署完成后应尽快改为用户个人密码。
