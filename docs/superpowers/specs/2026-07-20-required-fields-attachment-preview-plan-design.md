# 需求收集平台优化建设计划书

**项目名称：** 需求收集平台必填标识、附件预览及配套文档建设

**文档版本：** V1.0

**编制日期：** 2026年7月20日

**适用系统：** 需求收集平台

## 1. 项目背景

现有需求收集平台已经具备需求填写、草稿暂存、需求查询、需求处理、系统与版本管理、附件上传下载等能力。当前系统在实际使用中存在以下问题：

1. 业务表单没有清晰、统一地标明必填项和非必填项，用户只能在提交失败后判断字段是否必须填写，增加了理解和反复修改成本。
2. 现有技术资料分散在设计、部署和使用说明中，缺少一份面向本次改造、能够同时指导开发、测试、上线和运维的完整技术实现方案。
3. 现有使用说明按菜单组织，尚未按照需求填报人、需求处理人、系统管理员的业务职责形成分角色操作手册。
4. 现有附件功能支持图片预览，其余文件主要通过下载查看。业务希望图片、PDF、Word、Excel附件均可在线预览，同时保留原文件下载能力。

本计划在不引入登录、账号和权限系统的前提下，对上述问题进行集中改进。文档中的“角色”只表示业务职责，不表示系统已经具备角色权限隔离能力。

## 2. 建设目标

### 2.1 总体目标

在保持现有业务流程和前后端分离架构稳定的基础上，完成表单信息提示、附件在线预览、技术文档和操作手册四项建设，使用户清楚知道每个字段的填写要求，使常用附件能够在内网环境中安全预览，并为开发、测试、部署、运维和最终用户提供统一依据。

### 2.2 具体目标

1. 所有业务表单中的可填写字段明确显示“必填”“选填”或“条件必填”。
2. 查询筛选区域统一提示“筛选条件均为选填”，避免重复标识影响页面可读性。
3. 必填标识、前端校验和后端校验保持一致；草稿暂存继续允许字段不完整。
4. 支持JPG、JPEG、PNG、GIF、WEBP、PDF、DOC、DOCX、XLS、XLSX在线预览。
5. 图片和PDF直接预览；Word、Excel由服务器使用LibreOffice转换为PDF后预览。
6. 在线预览不覆盖、不替换原始附件，并始终保留原文件下载入口。
7. 按需求填报人、需求处理人、系统管理员三个业务角色形成操作手册。
8. 明确开发、测试、部署、验收和运维要求，保障改造可实施、可验证、可回退。

## 3. 当前系统概况与问题分析

### 3.1 当前技术架构

| 层次 | 当前实现 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite、Element Plus、Axios |
| 后端 | Java 17、Spring Boot 3.3、Spring Web、Spring Data JPA、Bean Validation |
| 数据库 | MySQL 5.7.32，Flyway管理结构变更 |
| 文件存储 | 服务器本地附件目录，数据库保存附件名称、类型、大小、校验值等元数据 |
| 部署 | Nginx托管前端静态文件并反向代理 `/api`，后端以Java服务运行 |
| 时间规则 | 业务时间统一按 `Asia/Shanghai` 解释和展示 |

### 3.2 当前业务能力

- 填写正式需求或暂存草稿。
- 按系统、版本、部门、填写人、时间、类型、状态、保存类型和关键词查询需求。
- 查看、编辑和删除需求。
- 在独立的“管理需求”页面填写需求状态、完成时间、处理人和完成情况。
- 维护系统名称、负责人、协助人、状态及系统版本。
- 上传、下载和删除图片、PDF、Word、Excel附件。
- 对附件执行扩展名、MIME类型、文件签名、路径和SHA-256校验。

### 3.3 主要问题

#### 3.3.1 字段填写要求不直观

部分控件虽然使用浏览器 `required` 属性或后端校验，但页面标签没有统一显示填写要求。条件必填字段会随所属系统选择变化，用户无法在填写前获得完整提示。编辑页、处理页和系统管理页也缺少统一规则。

#### 3.3.2 附件预览范围不足

当前详情页只对图片显示预览，附件获取接口固定以下载方式响应。PDF、Word和Excel无法在系统内形成一致的预览体验。对于内网部署，不能依赖要求文件公开访问的外部预览服务。

#### 3.3.3 角色说明不足

当前系统没有登录和权限模型，但实际使用中已经存在填报、处理和管理三类职责。现有说明没有按照职责拆分，用户需要自行判断应该使用哪些菜单和功能。

## 4. 项目范围

### 4.1 本期范围

- 新建需求、编辑需求、草稿编辑、处理需求、系统维护和版本维护表单的字段标识改造。
- 查询筛选区的统一选填提示。
- 前端字段提示、错误展示和首个错误字段定位。
- 后端正式提交校验规则核对与统一。
- 附件预览状态、预览接口、Office转PDF、预览缓存和清理机制。
- 图片、PDF、Word、Excel统一预览弹窗。
- 转换超时、失败、磁盘不足和服务不可用时的降级处理。
- 分角色操作手册、部署说明、运维说明、测试及验收方案。

### 4.2 本期不包含

- 登录、账号、组织机构、单点登录、角色权限或部门数据权限。
- 在线编辑Word或Excel内容。
- Office文档逐像素还原承诺；预览用于快速查看，正式内容以下载的原文件为准。
- 依赖互联网的第三方文件预览服务。
- 对当前业务无关的页面重构、审批流、通知和报表功能。

## 5. 必填与选填标识方案

### 5.1 统一展示规则

1. 必填字段在字段名称后显示红色“* 必填”。
2. 非必填字段在字段名称后显示灰色“选填”。
3. 条件必填字段在条件未触发时显示“条件必填”；触发后显示红色“* 必填”。
4. 每个业务表单顶部显示统一说明：“带 * 的项目为必填项，选填项目可根据实际情况填写。”
5. 校验失败后，在对应字段下方显示具体错误原因，并将页面定位到第一个错误字段。
6. 不只依赖颜色表达字段状态，文字标识必须始终可见，以兼顾可访问性。
7. 查询筛选区不逐项重复显示“选填”，在区域标题处统一显示“筛选条件均为选填”。
8. 草稿表单仍展示正式提交所需的必填标识，但点击“暂存”时允许内容不完整。

### 5.2 字段规则清单

| 场景 | 必填字段 | 选填字段 | 条件说明 |
|---|---|---|---|
| 新建/正式提交需求 | 姓名、部门、需求标题、类型、所属系统选择、需求内容 | 需求时间周期、目标版本、附件 | 所属系统允许选择“暂无系统”，但必须明确选择一种模式 |
| 选择已有系统 | 已有系统 | 目标版本 | 仅在所属系统模式为“已有系统”时显示 |
| 选择新系统 | 新系统名称、新系统负责人 | 新系统协助人 | 名称和负责人为条件必填 |
| 编辑正式需求 | 姓名、部门、需求标题、类型、状态、需求内容 | 所属系统、目标版本、需求周期、附件 | 停用系统和版本只允许保留历史值，不作为新选择 |
| 编辑草稿 | 正式提交所需字段继续显示必填标识 | 其他字段按正式规则显示 | 暂存时不执行完整必填校验，正式提交时执行 |
| 填写处理情况 | 需求状态 | 完成时间、处理人、完成情况 | 本期不新增状态联动必填规则 |
| 新增/编辑系统 | 系统名称、负责人 | 协助人 | 协助人支持多人并进行去重校验 |
| 新增/编辑版本 | 版本名称 | 无 | 版本名称在同一系统内不得重复 |
| 附件上传 | 无 | 附件 | 显示“选填；支持图片、PDF、Word、Excel，上传后可在线预览” |

### 5.3 前后端一致性

- 前端建立集中式字段规则和统一的字段标签组件，避免每个页面手工拼接不同样式。
- 正式需求提交、正式需求编辑和草稿转正式提交使用同一套校验定义。
- 后端继续作为最终校验边界，对必填、长度、枚举、日期范围、系统版本关系等进行校验。
- 前端收到后端字段错误后，应将错误映射回对应控件；无法映射的错误显示在表单顶部。
- 自动化测试同时验证可见标识和提交行为，避免页面显示“选填”但后端拒绝，或页面显示“必填”但后端接受空值。

## 6. 系统总体技术实现方案

### 6.1 总体原则

1. 保持现有Vue 3、Spring Boot、MySQL和服务器文件存储架构不变。
2. 采用最小改造方式增加表单标识和附件预览，不进行无关重构。
3. 原始附件与预览文件分离保存，预览异常不得影响原文件下载。
4. 所有文件处理均在内网服务器完成，附件不发送至外部服务。
5. 通过Flyway增量迁移数据库，不直接修改生产数据库结构。

### 6.2 模块划分

| 模块 | 职责 |
|---|---|
| 表单规则模块 | 集中定义字段显示状态、条件必填规则和前端错误映射 |
| 附件元数据模块 | 保存原文件信息、校验值、预览状态、预览路径和失败原因 |
| 预览服务模块 | 判断文件类型、直接返回可预览文件或调用转换服务 |
| Office转换模块 | 通过LibreOffice无界面模式将Word、Excel转换为PDF |
| 预览缓存模块 | 复用已生成PDF，控制预览目录、失效和清理 |
| 前端预览组件 | 统一展示图片、PDF和Office转换结果，并提供下载入口 |
| 运维监控模块 | 记录转换耗时、错误、磁盘空间、清理结果和服务可用性 |

## 7. 附件在线预览技术方案

### 7.1 格式处理策略

| 文件格式 | 处理方式 | 预览输出 |
|---|---|---|
| JPG/JPEG/PNG/GIF/WEBP | 使用已校验的原始文件 | 原图片 |
| PDF | 使用已校验的原始文件 | 原PDF |
| DOC/DOCX | LibreOffice无界面转换 | PDF |
| XLS/XLSX | LibreOffice无界面转换 | PDF |

### 7.2 处理流程

1. 用户上传附件。
2. 后端执行文件名规范化、扩展名、MIME类型、文件签名、路径和磁盘空间校验。
3. 文件写入临时文件，同时计算SHA-256校验值。
4. 校验通过后以随机存储名移动到原始附件目录，并写入附件元数据。
5. 图片和PDF立即标记为可预览。
6. Word和Excel标记为“待转换”，上传接口先返回成功，避免转换阻塞上传请求。
7. 后台转换任务读取附件，复制到独立临时目录并调用LibreOffice。
8. 转换成功后原子移动PDF到预览目录，更新状态为“可预览”。
9. 转换失败时记录简化后的失败原因和重试次数，状态变为“转换失败”。
10. 用户点击预览时，前端根据状态展示内容、等待提示或失败降级信息。

### 7.3 预览状态

建议定义以下状态：

- `DIRECT`：图片或PDF，可以直接预览。
- `PENDING`：Office文件等待转换。
- `CONVERTING`：正在转换。
- `READY`：转换成功，可以读取预览PDF。
- `FAILED`：转换失败，可下载原文件或重新生成。
- `UNAVAILABLE`：原文件丢失、被删除或预览服务不可用。

状态变化由后端控制，前端不得通过传参直接将附件标记为成功。

### 7.4 数据库改造

在附件表中增加以下字段，具体名称遵循现有数据库命名规范：

| 字段 | 含义 |
|---|---|
| `preview_status` | 预览状态 |
| `preview_relative_path` | 预览文件相对路径 |
| `preview_content_type` | 预览内容类型，转换结果为 `application/pdf` |
| `preview_generated_at` | 最近一次成功生成时间 |
| `preview_error_message` | 对运维有意义且不包含敏感路径的失败摘要 |
| `preview_retry_count` | 转换重试次数 |

数据库升级使用新的Flyway迁移脚本完成。原有图片和PDF数据可在迁移时根据内容类型初始化为 `DIRECT`，原有Word和Excel初始化为 `PENDING`，由首次访问或后台任务逐步生成预览，避免上线时一次性转换所有历史附件造成资源峰值。

### 7.5 接口设计

在保留现有上传、列表、下载和删除接口的基础上增加：

| 接口 | 用途 | 主要行为 |
|---|---|---|
| `GET /api/attachments/{id}/preview` | 获取预览内容 | 图片/PDF返回原文件，Office返回转换后的PDF；响应头使用 `inline` |
| `POST /api/attachments/{id}/preview/retry` | 重试生成预览 | 仅对Office转换失败或待处理文件生效，避免重复任务 |
| 附件列表响应扩展 | 展示预览状态 | 返回 `previewStatus`、`previewAvailable`、`previewContentType` |

下载接口继续返回原始附件，并使用 `Content-Disposition: attachment`。预览接口使用白名单内容类型和 `Content-Disposition: inline`，不根据客户端提供的内容类型直接响应。

### 7.6 缓存和一致性

- 预览PDF以附件ID和SHA-256组合生成存储名，确保原文件发生变化时旧缓存不会被误用。
- 同一附件同一时间只允许一个转换任务执行，可采用数据库状态条件更新或应用内互斥控制。
- 转换输出先写临时文件，验证PDF签名和非零大小后再原子移动到正式预览目录。
- 删除附件时同步软删除元数据，并清理原文件和预览文件。
- 清理失败时记录日志，由定时任务再次处理，业务层立即禁止继续访问。
- 预览目录可以随原始附件一起备份，也可以在恢复后按需重建；生产方案应在部署文档中固定一种策略。推荐备份原文件和数据库，预览缓存可重建，以减少备份体积。

### 7.7 LibreOffice运行方式

- 在服务器安装与操作系统兼容的LibreOffice稳定版本。
- 使用无界面参数启动转换，不运行桌面界面。
- 每个转换任务使用独立、可写的临时目录和用户配置目录，防止并发任务争用锁文件。
- 设置单任务超时、最大并发数和最大重试次数。
- 转换进程使用最小权限系统账号，不允许访问附件目录之外的业务路径。
- 任务结束后清理临时文件，无论成功或失败均不得残留原文档副本。

## 8. 前端交互设计

### 8.1 附件列表

附件列表显示文件名称、大小、类型、预览状态和操作按钮。操作至少包括“预览”“下载原文件”和现有权限范围内的“删除”。

- 可预览：显示正常的“预览”按钮。
- 转换中：显示“正在生成预览”，按钮不可重复触发。
- 转换失败：显示“预览生成失败”，提供“重新生成”和“下载原文件”。
- 不支持或服务不可用：说明暂时无法预览，保留下载入口。

### 8.2 统一预览弹窗

- 图片使用可缩放、可适应窗口的图片查看方式。
- PDF以及Office转换结果使用同一PDF预览区域。
- 弹窗标题显示原始文件名，不能将服务器随机存储名暴露给用户。
- 弹窗始终提供“下载原文件”入口。
- 预览失败时显示明确提示，不出现空白弹窗或无限加载。
- Office预览区域显示说明：“在线预览由系统转换生成，版式可能与原文件略有差异，请以下载的原文件为准。”

### 8.3 上传阶段预览

- 尚未上传的本地图片可以使用浏览器对象地址进行临时预览，并在组件销毁后释放地址。
- PDF、Word和Excel必须上传完成后使用服务器预览接口。
- 上传失败的附件不显示为已上传，不进入预览状态轮询。

## 9. 安全、性能与异常处理

### 9.1 安全要求

1. 保留现有扩展名、MIME类型、文件签名和SHA-256校验。
2. 文件访问只根据附件ID查询数据库保存的相对路径，不接受客户端传入任意服务器路径。
3. 原始目录、预览目录和临时目录必须规范化后验证根路径边界。
4. 预览响应只允许白名单图片类型和PDF，其他内容统一拒绝直接内嵌。
5. Nginx和后端配置 `X-Content-Type-Options: nosniff` 等必要安全响应头。
6. LibreOffice转换账号采用最小权限，转换任务设置CPU、内存、时间和并发边界。
7. 错误响应不返回服务器绝对路径、命令参数、数据库信息或堆栈。

### 9.2 性能要求

- 上传请求不等待Office转换完成。
- 转换任务默认并发数应根据服务器资源配置，初始建议为1至2个并发，再根据压测调整。
- 已成功生成的预览直接读取缓存，不重复启动LibreOffice。
- 前端状态查询采用有限次数和逐步延长间隔，避免高频轮询。
- 对超大文档、超多工作表或转换超时文件停止转换并降级为下载。
- Nginx可对预览文件启用受控缓存，但必须避免已删除附件继续被公开访问。

### 9.3 异常处理

| 异常 | 系统行为 | 用户提示 |
|---|---|---|
| 文件格式伪装或文件损坏 | 拒绝上传或转换 | 文件格式不正确或文件已损坏 |
| 附件目录空间不足 | 拒绝上传 | 服务器存储空间不足，请联系管理员 |
| 预览目录空间不足 | 保留原文件，转换失败 | 暂时无法生成预览，可下载原文件 |
| LibreOffice不可用 | 不影响上传和下载，记录失败 | 预览服务暂不可用，请稍后重试 |
| 转换超时 | 终止进程，清理临时文件 | 文件转换超时，请下载原文件查看 |
| 并发重复请求 | 复用已有任务 | 正在生成预览，请稍候 |
| 原文件不存在 | 返回404并记录一致性错误 | 附件文件不存在，请联系管理员 |
| 预览缓存损坏 | 清理缓存并允许重建 | 预览文件异常，正在重新生成 |

## 10. 分角色操作手册

### 10.1 角色说明

本系统目前不提供登录和权限隔离。下列角色按业务职责划分，用于说明不同人员通常需要完成的操作，并不限制其他人员访问现有菜单。

### 10.2 需求填报人

#### 10.2.1 新建需求

1. 在左侧菜单进入“填写需求”。
2. 阅读表单顶部说明，按“必填”“选填”和“条件必填”标识填写信息。
3. 填写姓名、部门、需求标题，选择BUG或需求类型。
4. 需求时间周期为选填；填写时必须同时选择开始和结束日期，且结束日期不得早于开始日期。
5. 选择所属系统模式：已有系统、新系统或暂无系统。
6. 选择已有系统时，选择系统；目标版本为选填。
7. 选择新系统时，填写系统名称和负责人；协助人为选填，多人使用逗号分隔。
8. 填写需求背景、问题、期望结果和验收标准。
9. 根据需要选择图片、PDF、Word或Excel附件。
10. 信息未完成时点击“暂存”；全部必填信息完成后点击“保存需求”。

#### 10.2.2 查看和预览附件

1. 进入“需求列表”，打开目标需求详情。
2. 在附件区域找到目标文件。
3. 点击“预览”。图片和PDF通常可立即打开；Word和Excel可能先显示“正在生成预览”。
4. Word或Excel转换完成后，系统以PDF形式展示。
5. 若预览失败，可点击“下载原文件”使用本地软件查看。
6. Office在线预览可能存在轻微版式差异，正式内容以原文件为准。

#### 10.2.3 查询和继续编辑

1. 进入“需求列表”，系统会自动加载需求。
2. 可使用系统、版本、部门、填写人、时间、类型、状态、保存类型和关键词筛选。
3. 打开草稿并继续编辑，可以再次暂存或正式提交。
4. 打开正式需求可查看详情和处理结果；执行编辑或删除前确认操作对象正确。
5. 若提示需求已被其他人修改，应刷新页面后重新操作。

### 10.3 需求处理人

1. 进入“管理需求”，查看暂存草稿和未完成的正式需求。
2. 打开目标需求，核对标题、内容、所属系统、目标版本和时间周期。
3. 预览或下载附件，了解完整业务背景。
4. 点击“填写处理情况”。
5. 选择需求状态：待评估、已确认、开发中、暂停、已完成、已拒绝或已关闭。
6. 完成时间、处理人和完成情况按实际情况填写，本期均为选填。
7. 点击保存。出现并发修改提示时刷新记录后重试。
8. 状态变为已完成、已关闭或已拒绝后，该需求从“管理需求”移除，但仍可在“需求列表”查询。

### 10.4 系统管理员

#### 10.4.1 系统和版本维护

1. 进入“系统管理”。
2. 新增系统时填写系统名称和负责人，协助人为选填。
3. 编辑系统信息，维护负责人和协助人。
4. 根据业务情况启用或停用系统。
5. 打开版本管理，新增或编辑版本名称，并按需要启用或停用。
6. 删除系统或版本前确认无关联需求；存在关联需求时先迁移需求。

#### 10.4.2 附件预览运维

1. 检查原始附件目录、预览目录和临时目录剩余空间。
2. 检查LibreOffice安装及转换账号的目录权限。
3. 查看后端日志中的转换超时、失败和清理错误。
4. 对偶发失败附件执行重新生成预览；连续失败时下载原文件验证文件是否损坏。
5. 定期检查预览缓存清理结果，避免孤立文件长期占用空间。
6. 备份数据库和原始附件目录；如不备份预览缓存，恢复后允许系统按需重新生成。
7. 系统迁移或恢复完成后，抽查图片、PDF、Word和Excel预览以及原文件下载。

### 10.5 常见问题

| 问题 | 处理方式 |
|---|---|
| 为什么草稿可以缺少必填内容 | 必填规则在正式提交时强制执行，暂存用于保存未完成内容 |
| Word或Excel预览为什么需要等待 | 系统需要先在服务器转换成PDF |
| 在线预览与原文件版式不一致 | 在线预览用于快速查看，应下载原文件确认正式版式 |
| 预览失败是否代表附件丢失 | 不一定；优先尝试下载原文件，预览失败不会覆盖原文件 |
| 系统或版本无法删除 | 存在关联需求时必须先迁移需求 |
| 保存时提示已被修改 | 其他人员已更新同一记录，需要刷新后重试 |

## 11. 实施计划与资源安排

### 11.1 基准资源

基准排期按1名全栈开发人员全程参与、1名测试人员在联调和验收阶段参与估算。若生产服务器安装软件、网络变更或上线审批需要独立流程，应在总体日期上增加相应等待时间。

### 11.2 基准排期

| 阶段 | 工期 | 主要工作 | 交付物 |
|---|---:|---|---|
| 需求与设计确认 | 1个工作日 | 核对字段规则、预览范围、异常提示和验收用例 | 确认后的计划与设计 |
| 必填标识改造 | 2个工作日 | 统一表单标签、错误提示、前后端校验和测试 | 表单改造版本 |
| 附件预览后端开发 | 2个工作日 | 数据库迁移、预览接口、转换服务、状态及缓存 | 后端预览服务 |
| 附件预览前端开发 | 2个工作日 | 附件状态、预览弹窗、失败降级、重新生成 | 前端预览功能 |
| 联调与测试 | 2个工作日 | 功能、安全、异常、兼容和回归测试 | 测试记录及问题清单 |
| 部署与验收 | 1个工作日 | 备份、安装LibreOffice、配置、升级和业务验收 | 上线版本及配套文档 |

总基准工期约10个工作日。该排期不包含外部审批等待、生产服务器采购或大规模历史附件预转换。

### 11.3 上线步骤

1. 完成代码评审和自动化测试。
2. 备份生产数据库和原始附件目录，并验证备份可读取。
3. 在服务器安装LibreOffice，创建预览和临时目录，配置最小权限运行账号。
4. 部署后端版本，由Flyway执行数据库增量迁移。
5. 部署前端静态资源并刷新Nginx配置。
6. 执行健康检查和核心业务冒烟测试。
7. 抽查历史图片、PDF、Word和Excel附件。
8. 业务代表完成验收后开放使用。

### 11.4 回退原则

- 上线前保留旧前端静态资源、旧后端程序包、数据库备份和附件备份。
- 发生严重问题时先停止新流量，恢复旧程序版本。
- 新增数据库字段应保持向后兼容，使旧程序忽略新增字段后仍可运行。
- 已生成的预览文件属于可重建数据，必要时可停用预览功能而不影响原附件下载。
- 如果数据库迁移必须回退，应使用经验证的恢复流程恢复上线前同一批次数据库与附件数据，不对生产表执行未经验证的手工删除。

## 12. 测试与验收标准

### 12.1 表单验收

1. 所有业务表单的可填写字段均显示必填、选填或条件必填状态。
2. 查询筛选区显示“筛选条件均为选填”。
3. 条件必填字段随所属系统模式正确变化。
4. 正式提交时前端和后端校验一致，错误准确定位到字段。
5. 草稿允许信息不完整，草稿转正式需求时执行完整校验。
6. 已有需求的编辑、保存和并发冲突提示不受改造影响。

### 12.2 附件验收

1. JPG、JPEG、PNG、GIF、WEBP可以在线预览。
2. PDF可以直接在线预览。
3. DOC、DOCX、XLS、XLSX可以转换为PDF并在线预览。
4. 所有支持格式均可下载原文件，文件名称和内容正确。
5. Office转换结果不会覆盖或更改原文件。
6. 转换中、转换失败、文件损坏、磁盘不足、超时和服务不可用均有明确提示。
7. 同一附件的并发预览不会无序重复转换。
8. 已完成预览可以复用缓存，响应时间明显低于首次Office转换。
9. 删除附件后原文件和预览均不可继续访问。
10. 中文文件名、多页文档、多工作表和常见Office内容能够正常处理。
11. 伪装扩展名、错误MIME类型和非法文件签名被拒绝。

### 12.3 回归验收

- 新建需求、草稿暂存、草稿转正式需求正常。
- 需求列表默认加载、组合筛选、分页、详情、编辑和删除正常。
- 管理需求状态和处理情况保存正常。
- 系统和版本新增、编辑、启停、迁移及删除限制正常。
- 原有附件上传、下载和删除功能正常。
- 上海时区的填写时间、完成时间和周期显示正常。

### 12.4 文档验收

- 技术方案覆盖架构、模块、数据、接口、安全、性能、异常、部署和回退。
- 操作手册按三个业务角色组织，并明确角色不代表权限隔离。
- 部署说明包含LibreOffice安装、预览目录、临时目录、环境变量和故障排查。
- 运维说明包含日志、磁盘检查、缓存清理、备份和恢复抽查。

## 13. 风险与保障措施

| 风险 | 影响 | 保障措施 |
|---|---|---|
| Office转换版式存在差异 | 用户误以为预览是正式原稿 | 明确提示以原文件为准，始终保留下载入口 |
| 大文件转换耗时或占用资源 | 后端响应变慢 | 异步转换、并发限制、超时、缓存和降级下载 |
| LibreOffice异常退出 | 单个或批量附件无法预览 | 独立进程、错误捕获、有限重试、日志和健康检查 |
| 预览文件增加磁盘占用 | 上传或转换失败 | 独立目录、空间阈值、删除联动、定时清理和监控 |
| 历史Office附件数量较多 | 上线后转换高峰 | 历史文件按需转换，不在上线时集中全量转换 |
| 字段标识和校验不一致 | 用户困惑或无法提交 | 集中规则、前后端测试和验收清单 |
| 当前无账号权限 | 各菜单和数据不能按角色隔离 | 文档明确职责边界；真实权限作为独立后续项目评估 |

## 14. 运维与持续改进建议

1. 将原始附件目录剩余空间、预览目录剩余空间、转换失败率和平均转换耗时纳入日常检查。
2. 对连续转换失败的文件类型和Office版本进行统计，定期更新兼容性清单。
3. 定期验证数据库备份和附件备份属于同一批次，并执行恢复演练。
4. 生产环境更新LibreOffice前先在测试环境回归常见DOC、DOCX、XLS、XLSX样本。
5. 若后续用户数量和并发量显著增长，可将转换任务迁移到独立工作进程或消息队列，但本期不提前引入额外基础设施。
6. 若后续需要真实角色权限，应单独设计身份认证、权限模型、数据范围、审计日志和现有数据归属，避免将业务职责说明误当作安全控制。

## 15. 结论

本方案在保留现有系统架构和业务流程的基础上，以统一字段标识解决填写要求不清的问题，以服务器端LibreOffice转换解决内网环境下Word和Excel预览问题，并通过分角色手册、实施排期和验收标准形成完整交付闭环。方案不依赖外部在线服务，原文件与预览文件相互隔离，转换失败时能够安全降级为原文件下载，适合当前系统规模和部署条件。
